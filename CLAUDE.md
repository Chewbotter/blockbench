# Blockbench fork: custom tools for Distant Early Warning

Personal fork of Blockbench 5.1.6 (JannisX11/blockbench). All work goes on branch `custom`. Since 2026-09-11 the fork takes no upstream updates: everything here is custom, core files may be changed freely, and anything upstream adds later gets re-implemented by hand if wanted. `master` just mirrors upstream.

## Roadmap (user, 2026-09-15)
The fork is permanent and refined for the long run; only official upstream updates are off the table. Three tracks, in this order: (1) performance for mid-poly meshes, 1 to 10k faces (done 2026-09-15/16 to the user's satisfaction: drags, undo, selection, UV panel; `probe_perf.mjs` and `probe_hitch.mjs` in the scratchpad pattern are the yardsticks: measure on the real file with the real keymap, fix one thing, re-measure); (2) importing models with a rig, and (3) textures up to 2048 x 2048, both now the current track: stabilise the import path first. Decided 2026-09-16 (user): the fork is the one-stop tool for anything low or mid poly; complex characters are bought or downloaded rigged (usually made in Blender, which is installed at `D:/Blender 5.2/blender.exe` and converts headless in under a second), imported as glTF, posed in the Animate tab, and the poses go to the game as a pose file keyed by bone name while the mesh stays the glTF it came as (Godot imports that natively). Re-exporting a mesh from the fork is the second step, only when a bought mesh gets edited here. An FBX or .blend converter through headless Blender is deferred until a model arrives without a glTF. Performance rule learned: a static probe misses costs that only appear while a selection is changing; replay the user's exact gesture on his file.

## Commands
- `npm run build-electron`: bundle, about half a second. After every change.
- `npm run dev`: dev app with remote debugging on port 9223.
- `npm run app`: packaged app in `dist-electron/win-unpacked`, plus `Blockbench.lnk` in the repo root. Fails while Blockbench is open (exe locked), so check `tasklist | grep -i blockbench` first and skip or ask.
- `node tests/dew/run_cdp.mjs tests/dew/<test>.mjs --isolated`: one scripted test over CDP. It reuses the dev app that is already up and leaves it running, so working on a test does not reopen a window every run (about 10 s the first time, 3 to 4 s after). `--isolated` uses a separate profile; required whenever the packaged app is open, and a shared app is restarted when a run asks for the other profile.
- `npm run test:dew:stop`: close the shared dev app.
- `npm run test:dew`: every test in sequence, each in its own app (`--fresh`), which also closes a shared one. Requested milestones only.
- `node tests/dew/run_cdp.mjs tests/dew/probe_keymap.mjs`: the user's live keymap, sub-keybinds included (run without `--isolated` so it reads his profile).

## Working rules
- Commit each verified change on `custom` without asking; never push (the user pushes from GitHub Desktop).
- Per change: build, run the test for the feature touched (not the whole suite), then `npm run app` and close the dev app (`npm run test:dew:stop`). Speed matters more than exhaustive testing right now.
- The package is what the user tests, so it must never be behind the code: a build 39 minutes old once produced a bug report for something already fixed, and the screenshots matched the old behaviour exactly. If `npm run app` is skipped because Blockbench is open, say so in the reply rather than letting it pass quietly.
- Simple heuristics over optimal ones. Every tunable is a named constant: `BRUSH` in `js/dew/tile_brush.js`, `DEW` in `js/dew/dew_scene.js`.
- No em dashes anywhere (code, comments, commits, replies). Use Bash, not PowerShell.
- The user builds all game content (rooms, clusters). Claude builds and tests tools only.

Sizes and positions in multiples of 4, minimum 4 (thin things are 4 thick in the file). Every fabric face owns its own atlas region at 1 texel per unit (the game paints damage there). The materials manifest is `textures/materials/materials.json` in the game repo, written by the game on every run: never hard-code the list or the scale. ### Code map
- `js/dew/dew_scene.js`: DEW Scene format, `DEW` constants, game grid, back-face tint on/off, per-project glTF export options, camera framing for new scenes. Back faces are culled in the viewport: `render_sides` returns 'front' while View > Hide Back Faces is on (the default), which also makes them unhittable, because the raycaster honours `material.side`. Clicks, the move gizmo and the tile tools all reach through a wall seen from behind, and the erase snapshot uses the same side so a drag cannot erase what is not drawn. The export is deliberately not affected: `export_render_sides: 'double'` keeps `doubleSided` true in the glb (a one-line hook in `js/lib/GLTFExporter.js`), since the handoff lists double-sided faces among the things the first export got right. The back-face tint is what you see when the toggle is off.
- `js/dew/tile_brush.js`: Tile Select, Tile Brush, Shave, Ramp, Texture Brush, Paint Bucket and their shared helpers (`describeTile`, `tileUV`, `blockTiles`, `atlasRegion`, `originCell`, `footprintCell`, `buildTileIndex`, `hitFace`, snapshot raycast for erasing). Two cells meet along the edge under the cursor, and the brush takes the one that closes a gap: `edgePoint` scores both sides with `fillScore`, where a cell already filled scores -1 and an empty one counts the tiles it would sit against in the same plane, and a tie keeps the far side, which is what still lands a wall started on a floor above it rather than under it. Only a face standing across the work plane offers a choice at all. Tab (`dew_tile_edge_side`) flips to the other side and resets when the brush is picked up. It shares its key with the ramp's own Tab action, and both declare `condition: {tools: [...]}` because `Condition.mutuallyExclusive` only reads object conditions, so a function condition there would have them flagged as conflicting in the keybind settings (`cdp_edge_side.mjs` checks both). Shave cuts outside corners at 45 degrees one block deep (16 or 32 per C, full size only on the 32 grid), keeps the touched side's texture, and closes the ends (trims end-plane tiles, adds or removes notch triangles). Ramp draws 45 degree faces from an edge: a piece started on a flat tile folds away from it (out across the edge, then out of the plane), one started on a diagonal continues that diagonal, and dragging adds further pieces in a straight line (`rampReach` counts them from the closest approach of the cursor ray to the run line). Starting on an inside corner still fills it as before, through `shaveTarget` / `shaveCorner` with the `inside` flag, and the run carries on from that slope's top edge. `run.min_pieces` is what a plain click places: 0 after a corner fill, 1 for a free diagonal. Free diagonals add no end triangles and delete nothing; only the corner case clears the tiles behind the slope. `shaveTarget` tries the hovered block's edges nearest first and takes the nearest one that carries a corner, so a hover anywhere on the tile works. End triangles cancel against a neighbouring cut of the same size, and nest by size otherwise (a smaller one is removed, a larger one already covers the end). After a stroke `capTriangularHoles` fills three-edge holes bordered by that stroke's faces: the gap left where a ramp meets flat tiles, or where two cuts meet. It matches edges by position, so a ramp in one element closes against a wall in another, and it runs after tile-brush painting too, so a wall painted beside a ramp closes itself. The search starts at an open edge of the stroke, but any edge can close the loop, open or not: a floor that carries on underneath a ramp shares that edge with the next floor tile, and requiring all three edges to be open used to leave exactly that gap open (`cdp_ramp_floor.mjs`). Whether a loop is really a hole is settled by the area and coverage tests, not by edge counts. Two things are not holes and are skipped: collinear loops (T-junctions between a long edge and two short ones) and loops a coplanar face already fills (a square wall tile closing the end of a wedge). The second test is the area the candidate shares with that face (`faceOverlaps`, Sutherland-Hodgman clipping, threshold `BRUSH.OVERLAP_AREA`), not whether its centre is covered: a face filling only part of a candidate leaves the centre clear, so a cap went on top of it and z-fought. The tests use the same two rules when counting holes. Neither tool responds on the back of a wall (no face there, so no corner) or at full size against a corner that is not on the 32 grid. The texture brush and the bucket also paint what is not a tile: a ramp diagonal or a cap triangle takes a cell through `faceFrame`, which builds a frame from the face's own normal (down follows gravity across the face, flat faces read like a floor, matching `tileUV`) and stretches the cell over the face's box, so a ramp reads like the tiles around it only longer. Atlas picks are counted in half cells whatever C says (`atlasRegion`). The texture brush lays the pick over its own footprint from the upper left as the texture reads (`footprintCell`): a pick smaller than the footprint repeats, so a full size brush with one cell paints all four tiles with it, and a larger one keeps its upper left cells. The fills (bucket, tile brush, Whole Block, all three sharing the pick) tile it from the plane origin instead (`originCell`), so separate strokes and blocks line up. A loose face has no grid to run along, so it takes the upper left of the pick, as much as the brush size holds and the hover lights the face itself rather than a cell. An atlas cell clicked again walks square, upper left half, lower right half (`ATLAS_SHAPES`, drawn on the overlay with a clip path); dragging past the cell goes back to squares. A triangle takes the half that is picked, turned 180 degrees about the cell centre when that is not the half it already lands on, which swaps halves without mirroring the art, so two triangles can share one cell. Quads always take the whole square. Ctrl with the Ramp tool erases instead of drawing: click or drag over a diagonal or a triangle to delete it (a red on-top ghost marks what will go), while flat tiles are left to the tile brush, so a mis-drawn slope comes off without undoing the whole run. It uses the same stroke-start snapshot raycast as the other erasers. Alt is the eyedropper on three tools: on the tile brush `pickTilePlane` takes the plane and the facing of the tile under the cursor, on the texture brush and the bucket `pickAtlasFromTile` takes the atlas cell that tile was painted with, reading it off the lowest uv corner of the face and selecting that texture. A picked facing lives in `state.sign`, where null means follow the camera as before, so tiles keep facing the way they were picked even after orbiting to the other side (where back-face culling then hides them, which is the point of Tab and W); W turns the plane and clears it. The plane grid's own lift still uses `facingSign`, since that is about drawing toward the viewer (`cdp_eyedropper.mjs`). Two costs are held down here (`cdp_paint_perf.mjs`): `buildOccupancy` and `buildTileIndex` are cached in `scan_cache` until `finished_edit`, `undo`, `redo` or `select_project`, since the hover path ran a whole-scene scan on every mouse move, and paint and erase steps call `scheduleRebuild` instead of `Canvas.updateView`, which collapses a drag crossing several tiles into one rebuild per frame (`cancelRebuild` in `endStroke` drops the frame the stroke's own final update covers). Anything mutating a scan must copy it first, as `startStroke` does; `shaveStep` rebuilds its index mid-stroke and so keeps calling `buildTileIndex` directly, while hovers use `hoverTileIndex`.
- Whole Block (`dew_whole_block`, between Tile Select and Tile Brush): drops a cube of half cell tiles into the cell under the cursor, on the near side of whatever it points at, falling back to the work plane over open space. C sizes it, W / A / D aim the plane, and a drag keeps the plane it started on so it lays a run rather than climbing what it just placed. It is an `atlas_picker` tool like the texture brush and shares its pick (`texture_state.atlas`): with a pick, every side a stroke adds is painted through `paintBlockSide`, which tiles a multi-cell pick from the plane origin the way the bucket does, so a row of blocks alternates cells unbroken; without one, sides stay untextured. Alt picks up a tile's cell (`pickAtlasFromTile`). A wall put back by Ctrl stays untextured. Culling only ever happens within one element: another element's face is left alone and the block adds its own side (unless the two would face the same way and z-fight), so separate objects stay whole when moved apart, and Cull Overlapping Faces remains the deliberate merge. Add DEW Block (`dew_add_block`, first in the outliner's + menu so the + button itself runs it in DEW scenes, and in the Mesh menu) starts a new element named `block` holding one block at the camera's orbit point snapped to the brush size, selected, so the tile tools build into it (`cdp_add_block.mjs`). Within an element: a side landing where a face already stands is skipped. That face goes too when it is the wall of a block on the other side, since it sits between two solids and back-face culling showed it from inside the neighbour; anything else (a floor, a lone wall) stays. Ctrl removes only what faces out of the cell, and gives a neighbouring block back the wall they shared. Both hinge on `blockOwner`: a cell counts as a block when faces point out of it on at least `BRUSH.BLOCK_SIDES` (2) sides besides the shared one. One side is not enough, because a floor tile is exactly the top of an empty cell under it, and taking that for a block hung walls under the ground (the old seal's bug, and test M). Known misjudgements: a hollow building made of outward-facing tiles looks like a block at its corners, so a block pushed against one there opens that wall; a block buried on all but one side looks empty, so its shared wall stays. One case still bites: a block placed under an existing floor takes that tile when it goes, since a face pointing the same way as the block's own side cannot be told apart from it. Undo is the way back (`cdp_whole_block.mjs`).
- Terrain Brush (`dew_terrain`, after Ramp in the toolbar, no key yet): raises the tile under the cursor a step (`BRUSH.TERRAIN_STEP`, 16, so 45 degrees), Ctrl lowers, Shift flattens (every cell a drag touches goes to the height under the cursor where the stroke started, snapped to a step, up or down; `settleTerrain` with dir 0, whose spread clamps neighbours both ways), C sizes it, a drag raises each cell once measured against the ground as the stroke found it, so it lays an even ridge. Ground is a height field over shared corner vertices, not stacked tiles: `buildGround` gathers the up-facing half cell faces of the hit element connected to the hit face (a floor on another storey stays out), and moving a tile's corners tilts its neighbours, so there are no connector pieces and nothing to leave a gap. `settleTerrain` spreads the change so no two corners a half cell apart differ by more than a step (axis neighbours only, so diagonal cells of a hill slope at about 55 degrees). Corners any non-ground face uses (a wall on the ground, the sides of a block, so a block top never moves) are pinned, and nothing else is, the cluster border included: a raise that would have to move one is tried one step shorter, then dropped. `refoldCell` keeps a cell a quad while its corners are planar and otherwise splits it into two triangles along the diagonal whose ends are closest in height, so one raised corner leaves a flat triangle; the split and the merge back carry each vertex's uv and the texture. Blockbench always triangulates a quad along its sorted 0-2 diagonal, which is why the fold is explicit faces rather than vertex order. Sloped cells are not tiles to `describeTile`, so the tile brush, Whole Block, Tile Select and Shave pass over them; the texture brush and bucket paint them as loose faces (`cdp_terrain.mjs`).
- `js/dew/dew_material.js`: the fabric contract. `new Property(Cube, 'object', 'game')` and the same on `Group` carry the tags through load, save, copy and undo (the stock constructors copy fixed field lists, so the reference file's `game` key was dropped before this); a `save_project` hook strips empty `game: {}`. The manifest is read through `fs` with an mtime check (`readManifest`, constants in `MATERIAL`: game dir, manifest path, models dir, atlas name and sizes); fill tiles load as pixel data per material. The Materials panel (`dew_materials`, right bar, DEW scenes) shows the palette as swatches from the fill PNGs with the display numbers on hover: click picks, double click applies to the selected cubes; it also shows the selected cubes' material, the selected group's kind with a dropdown to set it, the atlas usage, Reload and Save to game. `applyMaterial(cubes, name)` tags and fills: every face gets its own region of the scene's `atlas` texture (made on first use at 512, grown through `ATLAS_SIZES` up to 4096 when a face does not fit, or an Atlas full message), allocated bottom-left over the regions all cube faces already hold (`usedRegions` scans the scene, so an abandoned region frees itself; quadratic, fine for a room), the face uv set to that rectangle at 1 texel per unit and rotation 0, `box_uv` forced off. The fill is sampled by cube-space position (`faceFrame` uses `CubeFace.UVToLocal` plus origin, `fillPixels` steps the tile by axis sign), so brick courses run unbroken across touching unrotated cubes and along a rotated slab. A face already holding a region of the right size is repainted in place. `hasHandPaint` compares a face's region with what the fill would give and asks before refilling; `{force: true}` skips it. `Codecs.project.on('parsed')` applies the name fallbacks. Material Brush tool (`dew_material_brush`, after Terrain): click a cube to apply the picked material, Alt picks a cube's material up; Apply Material action for the selection; Save to Game Folder (`saveToGame`) writes `models/<name>/<Name>.bbmodel` from `Project.name`, after `validateFabric` (rules from the manifest's scale block via `fabricRules`: sizes and positions in multiples of `sample_units`, at least `min_thickness_units`, rotated cubes at least `ROTATED_MIN_SAMPLES` samples on every axis): offenders are listed in a message box and selected, and nothing is written. The interactive snap hangs off the format at module load: `Formats.dew_scene.edit_size` is a function (16 / the manifest sample, so a 4 step, or 16 for a 1 step while the Prop Snap toggle `dew_prop_snap` is on, Mesh menu) and `Formats.dew_scene.cube_size_limiter` is `fabric_limiter`, whose `clamp` Cube.resize already calls with the axis and the dragged side: a cube cannot be resized under 4, or 8 once rotated (rotating an existing 4 thick cube is caught by the save gate, not by the limiter). The reference grid draws 4 unit lines at `DEW.SAMPLE_LINE_OPACITY` between the half-cell lines (`cdp_fabric_snap.mjs`). `cdp_material.mjs` covers all of it against the real manifest and the reference file; `cdp_test_room.mjs` builds the section 8 room, saves it to `models/test_room/Test_room.bbmodel` and prints the report for the game side.
- `js/dew/dew_quads.js`: Merge Triangles into Quads (`dew_merge_triangles`, Mesh menu and a mesh's outliner menu, any format with a mesh selected). A glTF import is all triangles, so every diagonal is a face border and gets drawn; this joins pairs sharing an edge whose normals are within `QUADS.MAX_ANGLE` (5 degrees), same texture, continuous uvs across the shared edge, convex union, most rectangular pairs first, greedy. The quad keeps the pair's normal (the test's triangles face -y and so do its quads). It welds first (`weldVertices`, positions within `QUADS.WELD_DISTANCE`), since importers split vertices wherever normals or uvs differ and the user's first import had no two triangles sharing a vertex key at all; face uvs are per face so the weld loses nothing. When nothing merges the message says why (shared edges found, rejected by angle, uv seam, texture, concave), so a stubborn mesh can be read. Folded pairs, uv seams, texture changes and unpaired triangles stay (`cdp_quads.mjs`). MAX_ANGLE is 10 since 2026-09-15 (measured on the decimated revolver: of 3086 shared edges 786 were under 1 degree, 310 in 1 to 5, 216 in 5 to 10, 239 in 10 to 20; 5 merged 685 pairs). The seam rule applies to textured faces only: the glTF importer gives faces without a TEXCOORD channel placeholder uvs that differ on every triangle (`gltf_importer.js`, which also has its own consecutive-pair Merge Quads import option). Button only so far; auto-run after import is one hook once it has been seen on a real import. The same file extends the stock Turn Edges tool (`turn_edges_tool.onCanvasClick` wrapped at define time): with no hidden diagonal under the cursor, the nearest edge of the hit face is taken and, when exactly two triangles share it, flipped across the other diagonal (`flipSharedEdge`, uvs follow their vertices, the normal is kept); a quad edge does nothing and says so (`cdp_flip_edge.mjs`).
- `js/dew/dew_perf.js`: the mid-poly performance track. Wraps `Mesh.preview_controller.updateGeometry`: after a stock rebuild it caches the buffer layout (each vertex's slots, each face's slot range and first three sorted vertices, the outline, point and turn-edge orders), and the next update with unchanged topology (same face keys, same vertex lists, same vertex keys, same view mode) writes positions and flat normals straight into the existing typed arrays. Stock path when topology changed, in animate mode, with smooth shading or smoothing groups, weight views or wireframe, or with vertex offsets; after every `finished_edit` the fast-updated meshes get one stock rebuild (`PERF.FULL_REBUILD_ON_FINISH`), so cached quad sort orders are stale for one drag at most. `perf_stats` counts both paths for tests. Measured on the 100 x 100 grid (10k quads): stock rebuild 121 to 146 ms per drag frame, of which smoothing normals 21, per-face getNormal and sort 19, plain-array to typed-array conversion about 25; `probe_perf.mjs` prints the whole table, `cdp_fast_geometry.mjs` proves the fast buffers equal a full rebuild. The same file holds two more: a lean `MeshFace.prototype.getUndoCopy` (the stock one built a whole MeshFace through the constructor and deleted fields, 4.5 microseconds a face; the lean copy is the same four fields, uvs normalised as MeshFace.extend would, proven identical by `cdp_undo_copy.mjs`; an undo entry on 10k faces 94 to 42 ms), and an in-place `Mesh.preview_controller.updateSelection` (colours written into the existing typed arrays, object mode one fill, face mode integer pair keys, seam tool on the stock path; identical colours per `cdp_selection_colors.mjs`; object mode 13 to 0.3 ms, face mode 26 to 14). The UV panel cap is in core `js/uv/uv.js`: above `UVEditor.max_displayed_faces` (2000) a mesh shows only its selected faces and at most that many, with a note in the panel; select-all on 10k faces went from 3.9 s and 70k DOM nodes to 0.4 s and 14k, and UV moves still apply to every selected face (`cdp_uv_cap.mjs`). The remaining selection cost (about 20 ms per click at 10k faces) is spread over `updateNslideValues` (5), the status bar count (3), sliders and the transformer (2 each) and Vue work; the UV panel with one face selected still costs about 160 ms on a 10k mesh (the face list is enumerated even when few are shown). Stock behaviour kept reachable for tests as `DEWPerf.stockFaceUndoCopy` and `DEWPerf.stockUpdateSelection`. Posing (2026-09-16): `Armature.prototype.calculateVertexDeformation` is wrapped to gather each mesh's influences once from the bones' weight tables (`influence_cache`, cleared on `finished_edit`, `undo`, `redo`, `select_project`, `load_project`; the weight brush takes the stock path since it edits weights mid-stroke) and to build each bone's matrix once per call: 71 ms to 2.4 on the soldier's 4272 skinned vertices and 65 bones, offsets identical to 1e-14. `Mesh.preview_controller.displayDeformation` writes the deformed positions into the existing geometry and outline buffers when their sizes match the stock layout (faces in order, each face's vertices in its own order): 30 ms to 7. Both stock paths stay reachable (`stockCalculateVertexDeformation`, `stockDisplayDeformation`); `cdp_rig_import.mjs` compares them. Known stock quirk kept out of the cache: with more than four influences the stock sorts its bone list in place and drops the slice, ending up with the four smallest weights; the cache keeps the first four in armature order, and a glTF never carries more than four.
- `js/dew/dew_rig_import.js`: the character track. Import glTF with Rig (`dew_import_rig`, File > Import; also `Codecs.dew_gltf` with a `load_filter` on .gltf and .glb, so File > Open and drag and drop take a rigged file into a new generic project) parses through three's own `GLTFLoader` (`three/examples/jsm`, same module instance as the bundle's THREE); a .gltf's external buffers and images are inlined as data URIs first, since the renderer cannot fetch file paths. The whole file becomes ONE Armature (named after the single root node, else the file): every node is an ArmatureBone in the file's hierarchy, joints, control nodes and rigid pieces alike (a helmet hung on a head node is then posable like a joint), except a skinned mesh node, whose transform plays no part in its skin. Bone origin and rotation are the local transform relative to the nearest ancestor bone (three's world matrices, decomposed; a non-unit scale is reported since bones carry none), rotation in `Format.euler_order` degrees. Every mesh primitive is a Mesh under the Armature, origin at the node's world position, vertices in the scene's rest pose (`SkinnedMesh.boneTransform` for skinned ones, so any bind pose reads back as it looks), welded by position at `RIG.WELD_DISTANCE` (the soldier's 27k split vertices became 6k), weights from JOINTS_0 / WEIGHTS_0 through `setVertexWeight`, and a rigid piece weighted 1 to its own node's bone. Blockbench derives the bind from the bones' rest pose, so nothing of the file's inverse bind matrices is kept. Materials with a texture become Blockbench textures from the image (uv scaled by the image size, v from the top as in glTF); flat colours are baked into one `palette` texture, `RIG.PALETTE_CELL` pixels a cell with uvs a pixel in from its edges, colours converted linear to sRGB. Animations become keyframes on the bones, rotation as the euler difference to the rest rotation in the format's order (the armature animator adds euler components), unwrapped so consecutive keys never take the long way round, position as the difference to the rest origin; a track whose node is not a bone is counted and skipped. Import scale is `RIG.SCALE()`, the `model_export_scale` setting (16) the exporter divides by, so a Blender file at 16 units per cell and a Blockbench export both come back at size (the soldier stands 47). The import is one undo entry. Bone names are kept as the file had them: `ArmatureBone.name_regex` and `Armature.name_regex` (core) now sanitise only for bone rigs without `armature_rig`, because the free format had `bone_rig` and was turning `thigh.L` into `thighL`, and the game keys poses by those names. Export Poses (`dew_export_poses`, File > Export) writes `<Project.name>.poses.json`: every animation is one pose, sampled at its first keyframe (`samplePose`: `showDefaultPose(true)`, `stackAnimations([animation])`, read each bone's `scene_object` against its `fix_rotation` / `fix_position`, restore), listing only bones that moved by more than `RIG.POSE_EPSILON`, per bone `q` (local rotation relative to rest, x y z w, exact), `deg` (the same as `RIG.POSE_EULER_ORDER` euler degrees, for reading) and `pos` (translation from rest, only when moved). `format: dew_poses`, `version: RIG.POSE_FORMAT`. Proposed to the game side, not yet confirmed. The core glTF exporter (`Codecs.gltf.compile`, `armature: false`) writes the result back as one skin with every bone a joint, names kept, animations as clips (`cdp_rig_import.mjs` D and E, which also writes `Soldier_base_rigged.blockbench.gltf` to `%LOCALAPPDATA%/Temp/dew_rig_export` for a Godot check). The test fixture `tests/dew/fixtures/rig_fixture.glb` is made by `make_rig_fixture.py` under headless Blender (two bones, a skinned box, a flat colour, a 45 degree bend); the soldier section skips when the file is missing. Not covered yet: a .gltf with a separate .bin (only inlined-data files were tried), KHR texture transforms, vertex colours, morph targets, a second joint set (JOINTS_1), and a .glb that references external files.
- `js/dew/dew_atlas.js`: DEW Atlas button (flat-color test atlas).
- `js/dew/dew_group.js`: Group Tiles (moves the selected faces of every mesh into one new element, so a building can be duplicated, moved, rotated or deleted as a unit) and Rotate Group 90 CW / CCW, which turns vertices in place around the selection's own footprint instead of the scene origin, keeping every coordinate on the grid. All three sit in the Mesh menu. Cull Overlapping Faces, in an element's outliner context menu, finds cells where this element's tiles coincide with another element's (same plane and cell, facing ignored) and removes the tiles on both sides, deleting any element it empties; it is the one automatic overlap removal, run deliberately after moving a duplicate. Extrude Tiles pulls the selected tiles along the way they face and skins the sides with tiles of the same size, one per half cell, rather than the single tall quad the stock extrude leaves; the tiles travel on new vertices so the ones staying behind keep the ones they shared, and nothing is left where they were. Its dialog asks for a distance in tiles, where a tile is 32 units, 0.5 is a half cell and a negative pulls the other way. Group Tiles and Extrude Tiles sit in an element's outliner context menu beside Cull Overlapping Faces, and the Tile Select tool opens the same two on right-click. Rotation keeps the UVs glued to the faces: for walls that already matches the brush convention for the new facing, and for floors and ceilings it means the art turns with the building (`probe_rotate_uv.mjs` shows both).
- Moves snap in DEW scenes: the format declares `edit_size` (now the function above, formerly 1 for a 16 step) and `canvasGridSize` (`js/misc.js`) takes a format's step in place of the user's setting, so moves, arrow-key nudges and UV drags step by 16 while a DEW scene is open. Holding shift or ctrl still gives the user's own steps, and their setting is never written.
- Starter tile: `createStarterTile` gives a new DEW scene one full tile at the middle of the grid, four half cell faces from 160,160 to 192,192 on y 0, named `tiles` so the brush carries on painting into it. The middle of a 320 cluster is a corner of four tile cells rather than the middle of one, and this is the cell past it, which keeps it on the grid the brush snaps to. Tests clear it (`Mesh.all.slice().forEach(m => m.remove())` after `newProject`) since it would otherwise sit in every count.
- Scale figure: a 32 x 48 x 32 cube (`DEW.FIGURE_*`) created in new DEW scenes and toggled from View > Scale Figure, which rebuilds it if deleted. It is a normal element marked `export = false`, so the glTF exporter skips it and `hitFace` looks straight through it; any helper element marked that way is ignored by the tile tools.
- Saved view: a `.bbmodel` carries the view it was left in under `model.view.previews`, and opening it puts the camera back (`js/formats/bbmodel.js`, `cdp_saved_view.mjs`). The machinery was already there for session restore, where `editor_state` saves the same per preview camera, target, projection, zoom and angle; a normal save just never wrote any of it. This is the other branch of that block, so a file carries the view without the save paths and selection that `editor_state` also holds. Putting it back rides on the stock Save View per Tab setting, which is on by default.
- Deselect all in a DEW scene clears elements and every mesh face selection, at priority 10 over the stock handlers (`js/dew/dew_scene.js`). Those each own a slice: mesh faces only while the selection mode is not object, elements otherwise, UV faces when that panel has focus, so the key did different things depending on the tool. Undo does not put a deselect back, which is also true of the stock handler, checked against a generic model (`cdp_hotkeys.mjs`).
- Triangle count in the status bar (`js/interface/interface.js`, `updatePolyInfo`, refreshed with every selection update): the selection's triangles over the scene's, cubes at two per drawn face (a face with `texture === null` draws nothing), meshes at n - 2 per face, hidden elements and non-exported helpers left out of the scene count (`cdp_poly_count.mjs`).

## Traps
- A dev app reused between test runs keeps the bundle it started with, so the runner starts it again when `dist/bundle.js` is newer than `performance.timeOrigin` of the page. Reloading instead of restarting looks cheaper and is a trap: `Page.reload` takes Blockbench down with it, and waiting for `Blockbench` to be defined passes immediately on the page that is still up, so the test runs against the old bundle and lies. Three chased bugs today were stale code. A reused app also carries its view over, and a test that drags across the screen picks up whatever the path crosses, so the reset puts the camera back to a fixed place. `--fresh` (what the suite uses) has neither problem and is the one to trust when a drag test disagrees with itself.
- Face mode selection with Shift (`js/preview/preview.js`, `startPaintSelect`): a Shift + left press on a mesh face starts the fork's paint select (every face the cursor passes over is added); the same press over nothing starts the stock selection rectangle (`startSelRect`), whose shift handling adds the faces the rectangle touches to the old selection. Two traps met on the way: the default keymap makes Shift + left drag over nothing the camera zoom (`preview_zoom` is key 1 with shift), and the orbit controls only stand down when the pointer is over geometry, so the rectangle path parks `controls.enabled` until mouseup; and the stock `canvas_unselect` mouseup cleared the face selection after any shift click that hit nothing, which is now skipped while shift is held. The stock rectangle counts a face as inside when any edge touches the rectangle, so a box selects the faces it clips as well as the ones it contains (`cdp_area_select_faces.mjs`). A reported hitch while drag-selecting faces was measured against the pre-performance code and was not a regression (identical at 2k faces, worse before at 10k); it was the UV panel redrawing every selected face, with its four vertex handles each, on every mouse move of a growing selection, plus the stock rectangle appending vertices and faces with `safePush` and `includes`, quadratic in the selection. Fixed in two places: the UV panel draws no faces while a rectangle or a paint select is in progress and redraws on release (`UVEditor.defer_during_area_select`; `getDisplayedUVElements` reads `Preview.selected.sr_move_f` and `paint_move_f`, which are outside Vue reactivity, so `stopSelRect` and `stopPaintSelect` call `$forceUpdate`), and `viewportRectangleOverlap` dedupes through Sets. Worst frame during a box over 1225 faces: 158 ms to 38. The user's own confirmation: with the UV panel folded the drag was instant, open it slowed progressively. Second round, on the real revolver (4223 faces, the user's keymap has the area select on plain Left Click): the drawing deferral was not enough, since `UVEditor.loadData` still ran on every move from the global selection update and its `displayTools` slider refresh recomputed uv extents over every selected face, 170 ms a move (3.7 s over one drag, zero in a steady state, which is why a static probe missed it). `loadData` now returns early while a rectangle or paint select is in progress and the release handlers call it once. What remains per move at that size: the transform gizmo placement (`Transformer.updateSelection` via `center()`, about 18 ms), the colour pass and the rectangle test, all flat, none growing.
- Right-clicking in the preview reaches an element's own menu only when `Toolbox.selected.selectElements` is truthy, and every DEW tool sets it false. A tool that wants a context menu opens one itself from `onCanvasRightClick` and returns false, which stops the preview's camera menu opening as well.
- Settings live in the profile and survive a kill, so a format must never write one: whatever puts it back is skipped by a crash or a force-quit, and the value then applies to every other project. `dew_scene` had this with `edit_size`, which left generic models snapping by half cells, and now declares `Format.edit_size` for `canvasGridSize` to read instead. Anything else a format needs to change about the app belongs in the format, not in settings.
- An Electron window behind another window counts as occluded and stops producing frames: `Page.captureScreenshot` then waits a minute or more, and `requestAnimationFrame` may never fire. The runner launches with `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling`. Without them a reused app took 105 s for a test that takes 4. Never wait on rAF from a test for the same reason: render through `Preview.render()` instead.
- Performance, measured on a 3600 to 6400 tile mesh: a `Canvas.updateView` with `geometry: true` rebuilds that whole element, around 13 microseconds per face, so anything per-tile has to be batched. A whole-scene face scan is around 5 microseconds per face, which is why hover paths cache. Selection lookups used to be arrays scanned once per face (`selected_faces.indexOf(fkey)` in `updateHighlight`, the same shape for vertices and edges in `updateSelection`), quadratic in a big mesh, now Sets. Rendering itself is not the problem: 6400 tiles with everything selected still draws at 140 fps.
- The UV editor draws about 7 DOM nodes per face of every element it displays, so highlighting a few thousand tiles in face mode makes `updateSelection` take about 600 ms (44,000 nodes at 6400 faces). Object mode is cheap (88 nodes), and `getDisplayedUVElements` already returns `[]` for `atlas_picker` tools, which is where a cap would go. Not capped yet: it hides UV faces, which is the user's call (`probe_uv_cost.mjs` has the numbers).
- Keymap labels: a bracketed modifier ("[Ctrl] + [Shift] + Page Up") is optional, so the bare key is taken. Sub-keybinds (selection modes, slider nudges) are separate from action keybinds; check both before proposing keys.
- Project switch order: `ModelProject.select` loads its editor state, which selects the format (`select_format` fires while `Mode.selected` is still false), then restores the mode and the saved tool, then fires `select_project`. Switch tools or rebuild UI in `select_project`, never in `select_format`.
- Constructors copy fixed field lists. `Tool` and `ModelFormat` now keep unknown options (2026-09-11); `Action`, `BarSelect` and the rest still drop them.
- `Tool.onUnselect` runs before the next tool is selected: defer UI refreshes with `setTimeout(..., 0)`.
- `Texture.select` refreshes the UV editor only in paint mode; the atlas tools listen to `select_texture`.
- Render sides "auto" means double-sided, and the glTF exporter copies it into `doubleSided: true`.
- Selection undo follows the Undo Selections setting (default on in this fork since 2026-09-11). `Undo.finishSelection` cancels itself when nothing changed.
- Erasing during a drag raycasts a snapshot of the geometry from stroke start, or it drills through the holes it just made.
- In face selection mode `preview.raycast` can return vertex or edge hits in front of faces; use `hitFace`.
- CDP tests: a world point can project off the canvas; log the screen point when a click seems to do nothing. Image loads are async; wait before reading a new texture. After moving the preview camera, wait a frame before projecting world points: the matrix they project through only updates on render, so clicks land at the old view. The first hover after a camera move can still be aimed through the previous view, which shows up as a one-off flake; hover twice before asserting.
- Faces render from both sides in other formats, so a click passes to whatever surface is nearest, including the back of a floor between the camera and the target. DEW scenes cull back faces by default, so a click passes straight through them instead. A global Preview > Render Sides of 'double' overrides the format and brings the back faces (and the old behaviour) back.
- The tile tools snap blocks to multiples of the brush size, so geometry has to start on the 16 grid (32 for full size). Hand-built test geometry at, say, x 200 silently matches nothing; the brushes always build on-grid.
- Real scenes run past the 320 cluster square: the Warehouse floor (`D:/Work/DistantEarlyWarning/model_working/Warehouse.bbmodel`, read only) spans x -312 to 408 and z -24 to 536. The first terrain brush pinned everything at or beyond the square's edges and did nothing on most of that floor; the border lock was then dropped altogether (see the no cluster size decision above). `probe_terrain_warehouse.mjs` loads a copy (`PROBE_FILE=<path>`) and reports what the terrain brush sees.
