# Blockbench fork: custom tools for Distant Early Warning

Personal fork of Blockbench 5.1.6 (JannisX11/blockbench). All work goes on branch `custom`. Since 2026-09-11 the fork takes no upstream updates: everything here is custom, core files may be changed freely, and anything upstream adds later gets re-implemented by hand if wanted. `master` just mirrors upstream.

## Commands
- `npm run build-electron`: bundle, about half a second. After every change.
- `npm run dev`: dev app with remote debugging on port 9223.
- `npm run app`: packaged app in `dist-electron/win-unpacked`, plus `Blockbench.lnk` in the repo root. Fails while Blockbench is open (exe locked), so check `tasklist | grep -i blockbench` first and skip or ask.
- `node tests/dew/run_cdp.mjs tests/dew/<test>.mjs --isolated`: one scripted test against the dev app over CDP. `--isolated` uses a separate profile; required whenever the packaged app is open.
- `npm run test:dew`: every test in sequence. Milestones only.
- `node tests/dew/run_cdp.mjs tests/dew/probe_keymap.mjs`: the user's live keymap, sub-keybinds included (run without `--isolated` so it reads his profile).

## Working rules
- Commit each verified change on `custom` without asking; never push (the user pushes from GitHub Desktop).
- Per change: build, run the test for the feature touched (not the whole suite), then `npm run app` so the user can judge look and feel. Speed matters more than exhaustive testing right now.
- Simple heuristics over optimal ones. Every tunable is a named constant: `BRUSH` in `js/dew/tile_brush.js`, `DEW` in `js/dew/dew_scene.js`.
- No em dashes anywhere (code, comments, commits, replies). Use Bash, not PowerShell.
- The user builds all game content (rooms, clusters). Claude builds and tests tools only.

## Distant Early Warning
- Spec: `D:/Work/DistantEarlyWarning/distantearly_game/BLOCKBENCH_HANDOFF.md`, maintained by the game's own conversation. Read it, never edit it; flag problems to the user. The only thing ever written into the game repo is exported `.glb` files in `content/clusters/`. Values marked [proposed] there are not confirmed.
- Decided in this repo: glTF export scale 16 (a 16-unit cube is 1.0 in the .glb, the game imports at 0.6 m per glTF unit); no two-sided planes in the environment (fences and glass are half a tile thick, or props); a placed tile faces the camera side and its texture reads upright from that side.
- Scale: 1 unit = 1 texel; half cell 16, unit tile 32, storey 64, cluster 320 x 320 [proposed].

### Code map
- `js/dew/dew_scene.js`: DEW Scene format, `DEW` constants, game grid, back-face tint on/off, per-project glTF export options, camera framing for new scenes. Back faces are culled in the viewport: `render_sides` returns 'front' while View > Hide Back Faces is on (the default), which also makes them unhittable, because the raycaster honours `material.side`. Clicks, the move gizmo and the tile tools all reach through a wall seen from behind, and the erase snapshot uses the same side so a drag cannot erase what is not drawn. The export is deliberately not affected: `export_render_sides: 'double'` keeps `doubleSided` true in the glb (a one-line hook in `js/lib/GLTFExporter.js`), since the handoff lists double-sided faces among the things the first export got right. The back-face tint is what you see when the toggle is off.
- `js/dew/tile_brush.js`: Tile Select, Tile Brush, Shave, Ramp, Texture Brush, Paint Bucket and their shared helpers (`describeTile`, `tileUV`, `blockTiles`, `stampBlocks`, `buildTileIndex`, `hitFace`, snapshot raycast for erasing). Two cells meet along the edge under the cursor, and the brush takes the one that closes a gap: `edgePoint` scores both sides with `fillScore`, where a cell already filled scores -1 and an empty one counts the tiles it would sit against in the same plane, and a tie keeps the far side, which is what still lands a wall started on a floor above it rather than under it. Only a face standing across the work plane offers a choice at all. Tab (`dew_tile_edge_side`) flips to the other side and resets when the brush is picked up. It shares its key with the ramp's own Tab action, and both declare `condition: {tools: [...]}` because `Condition.mutuallyExclusive` only reads object conditions, so a function condition there would have them flagged as conflicting in the keybind settings (`cdp_edge_side.mjs` checks both). Shave cuts outside corners at 45 degrees one block deep (16 or 32 per C, full size only on the 32 grid), keeps the touched side's texture, and closes the ends (trims end-plane tiles, adds or removes notch triangles). Ramp draws 45 degree faces from an edge: a piece started on a flat tile folds away from it (out across the edge, then out of the plane), one started on a diagonal continues that diagonal, and dragging adds further pieces in a straight line (`rampReach` counts them from the closest approach of the cursor ray to the run line). Starting on an inside corner still fills it as before, through `shaveTarget` / `shaveCorner` with the `inside` flag, and the run carries on from that slope's top edge. `run.min_pieces` is what a plain click places: 0 after a corner fill, 1 for a free diagonal. Free diagonals add no end triangles and delete nothing; only the corner case clears the tiles behind the slope. `shaveTarget` tries the hovered block's edges nearest first and takes the nearest one that carries a corner, so a hover anywhere on the tile works. End triangles cancel against a neighbouring cut of the same size, and nest by size otherwise (a smaller one is removed, a larger one already covers the end). After a stroke `capTriangularHoles` fills three-edge holes bordered by that stroke's faces: the gap left where a ramp meets flat tiles, or where two cuts meet. It matches edges by position, so a ramp in one element closes against a wall in another, and it runs after tile-brush painting too, so a wall painted beside a ramp closes itself. The search starts at an open edge of the stroke, but any edge can close the loop, open or not: a floor that carries on underneath a ramp shares that edge with the next floor tile, and requiring all three edges to be open used to leave exactly that gap open (`cdp_ramp_floor.mjs`). Whether a loop is really a hole is settled by the area and coverage tests, not by edge counts. Two things are not holes and are skipped: collinear loops (T-junctions between a long edge and two short ones) and loops a coplanar face already fills (a square wall tile closing the end of a wedge). The second test is the area the candidate shares with that face (`faceOverlaps`, Sutherland-Hodgman clipping, threshold `BRUSH.OVERLAP_AREA`), not whether its centre is covered: a face filling only part of a candidate leaves the centre clear, so a cap went on top of it and z-fought. The tests use the same two rules when counting holes. Neither tool responds on the back of a wall (no face there, so no corner) or at full size against a corner that is not on the 32 grid. Ctrl with the Ramp tool erases instead of drawing: click or drag over a diagonal or a triangle to delete it (a red on-top ghost marks what will go), while flat tiles are left to the tile brush, so a mis-drawn slope comes off without undoing the whole run. It uses the same stroke-start snapshot raycast as the other erasers. Alt is the eyedropper on three tools: on the tile brush `pickTilePlane` takes the plane and the facing of the tile under the cursor, on the texture brush and the bucket `pickAtlasFromTile` takes the atlas cell that tile was painted with, reading it off the lowest uv corner of the face and selecting that texture. A picked facing lives in `state.sign`, where null means follow the camera as before, so tiles keep facing the way they were picked even after orbiting to the other side (where back-face culling then hides them, which is the point of Tab and W); W turns the plane and clears it. The plane grid's own lift still uses `facingSign`, since that is about drawing toward the viewer (`cdp_eyedropper.mjs`). Two costs are held down here (`cdp_paint_perf.mjs`): `buildOccupancy` and `buildTileIndex` are cached in `scan_cache` until `finished_edit`, `undo`, `redo` or `select_project`, since the hover path ran a whole-scene scan on every mouse move, and paint and erase steps call `scheduleRebuild` instead of `Canvas.updateView`, which collapses a drag crossing several tiles into one rebuild per frame (`cancelRebuild` in `endStroke` drops the frame the stroke's own final update covers). Anything mutating a scan must copy it first, as `startStroke` does; `shaveStep` rebuilds its index mid-stroke and so keeps calling `buildTileIndex` directly, while hovers use `hoverTileIndex`.
- `js/dew/dew_atlas.js`: DEW Atlas button (flat-color test atlas).
- `js/dew/dew_group.js`: Group Tiles (moves the selected faces of every mesh into one new element, so a building can be duplicated, moved, rotated or deleted as a unit) and Rotate Group 90 CW / CCW, which turns vertices in place around the selection's own footprint instead of the scene origin, keeping every coordinate on the grid. All three sit in the Mesh menu. Cull Overlapping Faces, in an element's outliner context menu, finds cells where this element's tiles coincide with another element's (same plane and cell, facing ignored) and removes the tiles on both sides, deleting any element it empties; it is the one automatic overlap removal, run deliberately after moving a duplicate. Rotation keeps the UVs glued to the faces: for walls that already matches the brush convention for the new facing, and for floors and ceilings it means the art turns with the building (`probe_rotate_uv.mjs` shows both).
- Moves snap to a half cell in DEW scenes: `canvasGridSize` is `16 / edit_size`, so the format sets `edit_size` to 1 on activation and restores the user's value on deactivation. That also makes arrow-key nudges and UV drags step by 16 while a DEW scene is open.
- Scale figure: a 32 x 48 x 32 cube (`DEW.FIGURE_*`) created in new DEW scenes and toggled from View > Scale Figure, which rebuilds it if deleted. It is a normal element marked `export = false`, so the glTF exporter skips it and `hitFace` looks straight through it; any helper element marked that way is ignored by the tile tools.
- Small core hooks: `js/preview/canvas.js` (`Format.buildGrid`, back-face uniforms), `js/shaders/{texture,marker,solid,layered}.frag.glsl` (back-face tint), `js/texturing/textures.js` (uniforms, atlas button), `js/uv/uv.js` (tools with `atlas_picker` make the UV editor show `Texture.selected`, receive `onAtlasClick`, and draw `atlas_overlay`), `js/interface/toolbars.js`, `js/main.ts`.
- Tile tool keys: click or drag paints, Ctrl erases or removes, Shift adds (select), W cycles the work plane, A / D step it a half cell, C switches full / half tiles, Alt picks up what is under the cursor (plane and facing on the tile brush, atlas cell on the texture brush and bucket), Tab flips the edge side under the Tile Brush and cycles the ramp direction under the Ramp tool (safe to bind: the key handler calls preventDefault whenever a keybind fires, so focus does not move; Tab still tabs normally under other tools). Bare keys still free: J K L N O Y [ ] 5 7 8 9 0.

## Traps
- Performance, measured on a 3600 to 6400 tile mesh: a `Canvas.updateView` with `geometry: true` rebuilds that whole element, around 13 microseconds per face, so anything per-tile has to be batched. A whole-scene face scan is around 5 microseconds per face, which is why hover paths cache. Selection lookups used to be arrays scanned once per face (`selected_faces.indexOf(fkey)` in `updateHighlight`, the same shape for vertices and edges in `updateSelection`), quadratic in a big mesh, now Sets. Rendering itself is not the problem: 6400 tiles with everything selected still draws at 140 fps.
- The UV editor draws about 7 DOM nodes per face of every element it displays, so highlighting a few thousand tiles in face mode makes `updateSelection` take about 600 ms (44,000 nodes at 6400 faces). Object mode is cheap (88 nodes), and `getDisplayedUVElements` already returns `[]` for `atlas_picker` tools, which is where a cap would go. Not capped yet: it hides UV faces, which is the user's call (`probe_uv_cost.mjs` has the numbers).
- Keymap labels: a bracketed modifier ("[Ctrl] + [Shift] + Page Up") is optional, so the bare key is taken. Sub-keybinds (selection modes, slider nudges) are separate from action keybinds; check both before proposing keys.
- Project switch order: `ModelProject.select` loads its editor state, which selects the format (`select_format` fires while `Mode.selected` is still false), then restores the mode and the saved tool, then fires `select_project`. Switch tools or rebuild UI in `select_project`, never in `select_format`.
- Constructors copy fixed field lists. `Tool` and `ModelFormat` now keep unknown options (2026-09-11); `Action`, `BarSelect` and the rest still drop them.
- `Tool.onUnselect` runs before the next tool is selected: defer UI refreshes with `setTimeout(..., 0)`.
- `Texture.select` refreshes the UV editor only in paint mode; the atlas tools listen to `select_texture`.
- Render sides "auto" means double-sided, and the glTF exporter copies it into `doubleSided: true`.
- Selection undo follows the Undo Selections setting (default on in this fork since 2026-09-11). `Undo.finishSelection` cancels itself when nothing changed.
- Erasing during a drag raycasts a snapshot of the geometry from stroke start, or it drills through the holes it just made.
- In face selection mode `preview.raycast` can return vertex or edge hits in front of faces; use `hitFace`.
- CDP tests: a world point can project off the canvas; log the screen point when a click seems to do nothing. Image loads are async; wait before reading a new texture. After moving the preview camera, wait a frame before projecting world points: the matrix they project through only updates on render, so clicks land at the old view. The first hover after a camera move can still be aimed through the previous view, which shows up as a one-off flake; hover twice before asserting.
- Faces render from both sides in other formats, so a click passes to whatever surface is nearest, including the back of a floor between the camera and the target. DEW scenes cull back faces by default, so a click passes straight through them instead. A global Preview > Render Sides of 'double' overrides the format and brings the back faces (and the old behaviour) back.
- The tile tools snap blocks to multiples of the brush size, so geometry has to start on the 16 grid (32 for full size). Hand-built test geometry at, say, x 200 silently matches nothing; the brushes always build on-grid.

## Current state (newest first)
- 2026-09-11: framerate work. A drag now rebuilds the mesh once per frame rather than once per tile (162 tiles: 26 rebuilds, not 162), hovers reuse the last scene scan (1.9 ms per move instead of 12.6 on 3762 faces), and the core selection lookups are Sets. The UV editor cost above is measured but not fixed.
- 2026-09-11: Alt eyedroppers. The three tools used to early-return on `altKey`, so the modifier was free.
- 2026-09-11: the tile brush picks the side of an edge that closes a gap instead of the outside, and Tab flips to the other side. The old rule came from the nudge off the hit surface in `getTarget`, which pushed the cell outward whenever the face stood across the work plane.
- 2026-09-11: back faces culled in DEW scenes, invisible and unselectable, as View > Hide Back Faces (default on). Export stays double-sided on purpose. Shift + drag multi-select on the Tile Select tool was reported broken but measures correct (`probe_select_shift.mjs`, and `cdp_select_bucket.mjs` D already covered it): plain drag 3 tiles, shift drag 6, full tiles 8 then 16, and Blockbench's own shift paint-select never runs for that tool because it sets `selectElements: false`. The likely cause of the report was back faces being hit through a wall, which is what the culling fixes.
- 2026-09-11: a cap is never laid over a coplanar face it shares area with. Reported as duplicate triangles z-fighting beside a ramp; three reproductions (one cell per stroke, one drag over several cells, a second pass over gaps already capped) all came back clean, so the user's exact scene is still unreproduced and the fix closes the one weakness the rule had rather than a confirmed case. `cdp_ramp_floor.mjs` has the overlap detector: exact repeats plus coplanar pairs whose centres fall inside each other.
- 2026-09-11: gaps beside a ramp close even when the floor carries on underneath it. Buried tiles under a slope are still left alone: removing them is the user's call, not the brush's.
- 2026-09-11: Ctrl erases ramp faces (diagonals and triangles only). Gap filling works in both orders, ramp-then-tiles as well as tiles-then-ramp; a cap copies its texture from the tile it borders, so caps beside brush-painted tiles are untextured until those tiles are textured.
- 2026-09-11: Cull Overlapping Faces; Group Tiles and 90 degree in-place rotation, half-cell move snapping; scale figure in new DEW scenes; Ramp tool; corner cleanup (end triangles nest by size, three-edge holes capped).
- 2026-09-11: Shave tool (outside corners only; undo is the only way back for now; the texture brush and bucket do not paint diagonal or triangle faces yet).
- 2026-09-11: Tile Select and Paint Bucket; multi-cell atlas stamps; Texture Brush and DEW Atlas; erase no longer drills through; back-face tint; Tile Brush; DEW Scene format. Earlier fork features (fit view, welding mode, turn edges, chamfer, auto unwrap and more) are in `git log`.
- Open, not designed yet: move / group / flip for selected tiles; slopes (proposed: tile corner heights in 4-unit steps, Turn Edges picks the fold); diagonal walls; material and cluster edge tags; one-click export to the game folder; stable element names (proposed: element id in glTF node extras, since Blockbench names are neither unique nor stable).
